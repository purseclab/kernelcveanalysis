# Local-app requirements for file write and code execution

This report inspects PoCs, source, and recorded results in `research/followup_runs/`, `research/android-bench/runs/opus5/`, `research/android-bench/runs/opus5_auto/`, and [Initial Opus.md](<Initial Opus.md>). **No PoC was run for this report.** “Demonstrated” means an earlier run recorded the target-side effect. An installed attacker APK is distinct from the ADB runner: when a script uses ADB to grant the *victim's* normal first-run permission, restart it, or inspect a private marker, the table identifies that separately. A local app's mere presence is insufficient in the rows below; the user must launch it once, or the PoC harness must launch it, unless a row says otherwise.

## Demonstrated file writes that use a local attacker app

The **Intent / IPC** column says what the APK sends to the target. **Bytes / provider** says whether the APK supplies file contents or only a path. **Target lifecycle** separates what the APK can initiate from what the test runner did. “Arbitrary” in an older PoC title does not imply unrestricted destination *and* unrestricted bytes.

## Demonstrated code execution reached through a local app

The first four rows are **local code-execution chains**: attacker code or bytecode ran under the target UID following an APK-origin trigger. The target restart column is especially important: an ADB `force-stop` in a runner is evidence of a required lifecycle transition, not a capability of the malicious APK.

| Target and result | Intent / IPC sent by local app | Payload supplied by local app | Target start / stop / restart | Limits and recorded evidence |
| --- | --- | --- | --- | --- |
| **PDF Reader ART image**, strongest path-repair variant. [PoC 3](../../../followup_runs/ru.androidtools.basicpdfviewerreader/exploit-3-art-path-repair-code-execution/README.md), [earlier calibrated PoC 2](../../../followup_runs/ru.androidtools.basicpdfviewerreader/exploit-2-art-image-code-execution/README.md), [findings](../../../followup_runs/ru.androidtools.basicpdfviewerreader/FINDINGS.md). | Zero-permission APK starts exported `MainActivity` with `ACTION_VIEW` to its PDF provider; the same `_display_name` traversal targets `cache/oat_primary/arm64/base.art`. | Provider serves a patched ART app image. Injected DEX bytecode in `App.onCreate` writes the marker **only after ART loads it**; the provider does not write that marker. | APK triggers the overwrite, but **cannot force the later target restart** shown by the PoC. ADB force-stops/starts PDF Reader to demonstrate execution; a real attack needs a later natural or attacker-reachable restart. | Path-repair removed the hard-coded randomized APK path and survived a same-boot reinstall, but still needs calibrated mapped image base, copy-time source offset, compatible boot/OAT metadata, and an existing original image. Target has to pass All files access onboarding. The injected method skips normal initialization, so the app crashes after writing `pwned.txt`. The Opus file-write attempt was unfinished; the follow-up verified both write and execution. |
| **Comic Reader ART image**. [PoC 4](../../../followup_runs/file_write_paper/ru.androidtools.comic_book_magazine_reader_cbr_cbz/poc-04-local-art-image-code-execution/README.md), [current findings](../../../followup_runs/file_write_paper/ru.androidtools.comic_book_magazine_reader_cbr_cbz/FINDINGS.md). | Zero-permission APK starts exported `MainActivity` with its provider URI; `_display_name` traversal targets `cache/oat_primary/arm64/base.art`. | Provider serves a patched, installation-specific ART image. Injected `App.onCreate` bytecode, rather than the provider, writes `/sdcard/Download/pwned.txt` after restart. | APK plants the image. **ADB force-stop and restart** in the PoC trigger the code; the APK is not shown forcing that restart. | Needs Comic Reader's All files access and a same-installation, same-boot ART image with measured mapped base and matching APK path/firmware data. The marker appears before the app crashes from skipped original initialization. This follow-up overturns the earlier Opus conclusion that its tier-3 write had no code-execution path. |
| **SHAREit SplitCompat/MMKV library**. [Local PoC](../../../followup_runs/com.lenovo.anyshare.gps/poc2-local-app-code-exec/README.md), [results](../../../followup_runs/com.lenovo.anyshare.gps/RESULTS.md). | `HybridLocalActivity` intent loads APK-hosted page; bridge sets storage root, writes split/library, and later calls `uploadFile` for proof. | APK serves unsigned split ZIP and ARM64 `libmmkv.so`; SHAREit writes them into its own private SplitCompat tree. This is delayed execution; it did not execute in the already-running SHAREit process. The earlier Opus traversal/SplitCompat chain was only a static lead; the follow-up observed this chain. A different remote-page PoC removes the local APK requirement but adds agreement/UI conditions. |
| **Element SoLoader/Jitsi library**. [Local PoC](../../../followup_runs/im.vector.app/exploit_local_code_execution/README.md), [current findings](../../../followup_runs/im.vector.app/FINDINGS.md). | APK sends nested `Parcelable` intents through exported `Alias`: one to uCrop to plant the library, then one to internal `JitsiMeetActivity` to request React Native/Jitsi loading. The optional grant stage targets its own receiver. | APK's loopback server supplies `libreactnativejni.so`; uCrop writes it to Element's `lib-main/`, then SoLoader loads that shadow copy and its constructor writes the marker. | **No restart between planting and triggering** was needed in the fresh-process PoC. The harness force-stopped Element before planting as setup; the APK itself can start both relevant activities through the alias. If the genuine library is already loaded in a running process, a later fresh process may be needed; that state was not tested. | APK has ordinary `INTERNET`; no user tap or Element login was needed. The demo stub lacks JNI methods, so Jitsi crashes *after* the constructor proves execution. Original Opus observed stages but never ran its final wrapper; the follow-up rebuilt and ran the packaged PoC end to end twice. |

**Related app-assisted remote execution:** Element's separate [Duktape/Jitsi `config.js` PoC](../../../followup_runs/im.vector.app/exploit_remote_code_execution/README.md) also installs a small local launcher, but that APK is used to enter a Jitsi meeting on an unconfigured emulator. It does **not** plant code or perform the memory corruption. The server-supplied `config.js` produced native execution in the running target; the normal logged-in Matrix widget delivery route was traced in source but not exercised end to end. SHAREit's [separate remote page RCE](../../../followup_runs/com.lenovo.anyshare.gps/poc1-remote-code-exec/README.md) used **no** attacker APK, though it required user interactions and All files access. SHEIN's GPT [network-template execution](../../../followup_runs/runs/gpt_6_sol/com.zzkko/FINDINGS.md) required a trusted-CA network position, not a local attacker app.

| Earlier Opus state | Current demonstrated state |

| [SHAREit](../../../android-bench/runs/opus5/com.lenovo.anyshare.gps/RESULTS.md): bridge traversal and SplitCompat chain were untested leads. | [Follow-up](../../../followup_runs/com.lenovo.anyshare.gps/RESULTS.md): external-tree write, private split/library write, and local cold-start code execution observed. |
| [Comic Reader](../../../android-bench/runs/opus5_auto/ru.androidtools.comic_book_magazine_reader_cbr_cbz/RESULTS.md): file write verified; no code execution then. | [Follow-up](../../../followup_runs/file_write_paper/ru.androidtools.comic_book_magazine_reader_cbr_cbz/FINDINGS.md): calibrated ART image produced local code execution after restart. |
| [Element](../../../android-bench/runs/opus5_auto/im.vector.app/RESULTS.md): local grant, write, and native load seen by stages, but final wrapper unrun. | [Follow-up](../../../followup_runs/im.vector.app/FINDINGS.md): packaged local chain ran end to end; the separate config-based execution has the delivery caveat stated above. |
| [FBReader](../../../android-bench/runs/opus5_auto/org.geometerplus.zlibrary.ui.android/RESULTS.md): import wrote only to a shared Books tree; private traversal failed. | [Follow-up](../../../followup_runs/org.geometerplus.zlibrary.ui.android/poc-05-private-file-write/README.md): a different downloader/config chain created a victim-private file after two user taps; overwrite and code execution remain unproven. |

**Not counted:** APUS auto's Zip-Slip was demonstrated only in its attacker harness, not the launcher; its cloud-config code execution used root-staged material ([assessment](../../../android-bench/runs/opus5_auto/com.apusapps.launcher/RESULTS.md)). SHEIN's offline-package traversal was source-only and no local app delivered it ([assessment](../../../followup_runs/file_write_paper/com.zzkko/RESULTS.md)).
