# Intent-sending capabilities in the benchmark runs

This is an inspection of PoC source, existing run logs, findings, and [Initial Opus.md](<Initial Opus.md>). The scope is `research/followup_runs/` (including its `file_write_paper/` and `runs/gpt_6_sol/` directories) and `research/android-bench/runs/opus5/` and `opus5_auto/`. I did **not** run any PoC. “Observed” below means the *earlier run's* artifacts show delivery or a target-side effect; it is not a fresh reproduction. I count distinct delivery mechanisms once, even where a PoC was copied into a follow-up folder. In particular, the Comic Reader PoC under `followup_runs/file_write_paper/` duplicates the Opus auto PoC.

“Arbitrary” needs a qualifier here. An `intent:` URL can encode an action, data URL, MIME type, categories, package, flags, and **typed scalar** extras. It cannot encode a nested `Parcelable` Intent, a `Uri` object extra, `ClipData`, a `Bundle`, or an arbitrary Java `Serializable` object. Android may parse more scalar type tags than any one PoC actually tested. The browser or receiving app can further remove fields, and an implicit intent still has to match an exported activity's filters. A URL string in an extra is not the same as a typed `Uri` extra or a URI permission grant.
